# Use of AI Tools: Guidelines & Reflection

## Research & Learning

### 1. AI Tools for QA & Development
For my role as a QA Intern, common tools include:
*   **ChatGPT/Claude:** For explaining logic, summarizing research, and drafting documentation.
*   **GitHub Copilot:** For real-time code suggestions and writing boilerplate test cases.
*   **AI-Powered Testing Tools:** Tools that can help generate test scripts based on UI descriptions.

### 2. Benefits vs. Risks
*   **Benefits:** Faster documentation, quicker debugging of common errors, and help with learning new syntax (like Pywinauto).
*   **Risks:** "Hallucinations" (AI giving confident but wrong answers), code that contains security vulnerabilities, and the risk of "thinking less" by copy-pasting without understanding.

### 3. What NEVER to enter into AI
I will never enter:
*   **API Keys or Passwords.**
*   **Customer Personal Data (PII).**
*   **Proprietary non-public business strategies.**
*   **Sensitive internal credentials.**

### 4. Fact-Checking Strategy
I will validate AI output by:
*   **Running the code:** Never assume AI code works until it passes in my terminal.
*   **Official Documentation:** Comparing AI advice against the official GitHub, Python, or Pywinauto docs.
*   **Peer Review:** Asking a teammate if a logic pattern suggested by AI is the preferred way at Focus Bear.

---

## Reflection

### AI vs. Personal Skill
I will use AI for "low-level" tasks like boilerplate code or finding a specific function name. I will rely on my own skills for "high-level" tasks like designing the overall test strategy and making final decisions on app quality.

### Avoiding Over-reliance
To avoid over-reliance, I will always try to solve a problem manually for 10-15 minutes before asking an AI. This ensures my own problem-solving muscles stay strong.

### Data Privacy
I will ensure that any code I share with a public AI is "sanitized" (generic versions of the code with no private details) to protect Focus Bear’s intellectual property.

## Practical Task Summary

### Task: Onboarding Documentation
I used an AI assistant to help structure my research for the "Competitive Landscape" and "Clean Code" modules.

### Critical Review
The AI provided a great structure, but I had to edit it significantly. For example, it made claims about competitors being "the only one" to do something, which I had to fact-check and soften to ensure accuracy. I also had to add my own personal reflections to the "Company Mission" section because the AI's version was too generic.

### Best Practice
**My Rule:** I will never commit AI-generated code or text without reading every single line and being able to explain exactly how it works to a teammate.
